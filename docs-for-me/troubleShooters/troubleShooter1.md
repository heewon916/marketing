# 트러블슈팅 정리 (2026-04-29 세션)

## 1. 한글 주석 깨짐(인코딩) 문제
### 문제 상황
- Windows 환경에서 로컬로 생성한 Java 파일(`RefreshToken.java`, `User.java`, `CustomOAuth2UserService.java`) 내의 한글 주석들이 `??` 또는 특수문자 조합으로 깨져서 표시되는 문제 발생.
- 이는 파일을 저장할 때의 기본 인코딩(CP949)과 파일을 읽어들일 때의 인코딩(UTF-8)이 불일치하여 발생한 현상.

### 해결 방법
1. **파일 복구**: 깨진 문자열 주변의 변수명 및 비즈니스 로직(예: 소셜 로그인 제공자 식별, 기존/신규 유저 처리 로직 등) 문맥을 파악하여 올바른 한글 주석으로 내용 복원 후 `UTF-8`로 저장.
2. **`.editorconfig` 도입**: 프로젝트 최상단 경로에 `.editorconfig` 파일을 추가하여, 팀 내 모든 에디터(IntelliJ 등)가 프로젝트 파일을 열고 저장할 때 강제로 `UTF-8` 인코딩을 따르도록 설정 공유.
3. **Gradle 빌드 설정 추가**: `be/build.gradle`의 Java 컴파일 작업(`tasks.withType(JavaCompile)`)에 `options.encoding = 'UTF-8'` 속성을 추가하여 어떤 환경에서도 안전하게 빌드되도록 강제.

## 2. 인스타그램 OAuth2 로그인 후 리다이렉트 주소 하드코딩
### 문제 상황
- 백엔드의 인스타그램 로그인 인증 성공 핸들러(`OAuth2AuthenticationSuccessHandler.java`)에서, 토큰 발급 후 클라이언트에게 전달하기 위한 리다이렉트 주소가 임시 테스트용인 네이버(`https://www.naver.com`)로 하드코딩 되어 있었음.

### 해결 방법
- 해당 리다이렉트 URL을 팀 규칙에 명시된 프론트엔드 외부 배포 서버 주소인 `http://k14a401.p.ssafy.io`로 수정.
- 이로써 로그인 성공 시, 실제 서비스 환경에서 프론트엔드가 URL 파라미터로 넘어온 토큰(`?token=...`)을 정상적으로 수신하고 후속 인증 처리를 진행할 수 있도록 연결.
