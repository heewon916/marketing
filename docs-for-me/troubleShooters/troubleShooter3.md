# Docker 기초 및 명령어 설명: 이미지를 새로 굽는다는 것

이 문서는 개발 중 자주 마주치는 Docker 개념과 `docker compose up -d --build` 명령어의 의미를 쉽게 이해하기 위해 작성되었습니다.

---

## 1. Docker '이미지(Image)'란 무엇인가요?

**이미지는 '완벽하게 세팅된 밀키트(Meal Kit)' 또는 '붕어빵 틀'과 같습니다.**

우리가 컴퓨터에서 어떤 프로그램(예: Spring Boot 서버)을 실행하려면 자바(Java)도 깔아야 하고, 환경 변수도 설정해야 하고, 여러 가지 복잡한 세팅이 필요합니다. 컴퓨터마다 환경이 달라서 "내 컴퓨터에선 되는데 네 컴퓨터에선 안 돼!" 하는 일이 자주 발생합니다.

이 문제를 해결하기 위해, **"이 프로그램이 실행되는 데 필요한 모든 것(코드, 자바, 설정 파일 등)을 하나의 파일로 꽁꽁 얼려버리자!"** 하고 만든 것이 바로 **Docker 이미지(Image)**입니다. 
한 번 이미지를 만들어 두면(밀키트 포장), 어떤 컴퓨터든 도커만 깔려 있으면 똑같은 맛(똑같은 실행 결과)을 낼 수 있습니다.

## 2. '컨테이너(Container)'는 무엇인가요?

**컨테이너는 만들어진 이미지를 바탕으로 '실제로 끓여낸 요리' 또는 '찍어낸 붕어빵'입니다.**

얼려둔 이미지(밀키트)를 도커를 이용해 실행시키면, 그것이 살아서 움직이는 상태가 되는데 이를 **컨테이너**라고 부릅니다. 
명령어 `docker compose up -d`를 치면, 도커가 밀키트(이미지)를 뜯어서 요리(컨테이너)를 시작하는 것과 같습니다.

## 3. 그렇다면 "이미지를 새로 굽는다(--build)"는 무슨 뜻인가요?

여기서 아주 중요한 포인트가 있습니다! 

코드를 열심히 수정했다고 가정해 봅시다 (예를 들어 새로운 API를 만들거나 오타를 고침). 
그런데 도커는 **기존에 만들어 둔 예전 이미지(밀키트)를 그대로 보관**하고 있습니다. 만약 `--build` 옵션 없이 그냥 실행만 하라고(`up`) 명령하면, 도커는 냉장고에서 "어? 밀키트 있네?" 하고 **수정되기 전의 옛날 코드로 요리를 해버립니다.**

그래서 우리가 **"코드 레시피가 바뀌었으니까, 옛날 밀키트는 버리고 방금 수정한 최신 코드를 넣어서 밀키트를 새로 포장해!"** 라고 명령해야 합니다. 
이 과정을 **빌드(Build)**한다고 표현하고, 한국 개발자들끼리는 빵이나 CD를 굽듯이 **"이미지를 굽는다"**라고 재미있게 표현하는 것입니다.

### 💡 요약 명령어 비교:

*   **`docker compose up -d`** 
    *   의미: (냉장고에 있는 밀키트로) 요리해 줘!
    *   결과: 코드를 수정해도 옛날 코드로 실행됨.
*   **`docker compose up -d --build`**
    *   의미: (변경된 최신 코드로 밀키트를) 새로 만들어서 요리해 줘!
    *   결과: 방금 수정한 코드가 안전하게 적용되어 최신 서버가 실행됨.
